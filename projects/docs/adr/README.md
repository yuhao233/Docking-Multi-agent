# 架构决策记录（ADR）索引

本目录保存**影响面大、后来者需要知道「为什么这么定」**的架构决策。每条 ADR 一个文件，
命名 `NNNN-短标题.md`（四位序号，从 0001 起，不跳号、不重用）。

| 编号 | 标题 | 状态 | 决策要点 |
| --- | --- | --- | --- |
| [0001](0001-agent-surface.md) | Agent 面的切分（产品面 / 平台面并存） | 已接受 | 网页与外部脚本走 `src/docking_agent/api/` 的产品接口；`langgraph-deploy/` 提供真正的 LangGraph Platform 面（Studio/SDK/durable 演进路径），两者共用同一套 Agent 图与产物 |

## 什么时候该写 ADR

满足任一条就写：

- 引入/删除一个**对外形态**（接口面、部署形态、打包方式）；
- 在两个都能工作的方案之间做了取舍，且**后来者很可能想改回去**；
- 定下一条会长期约束代码结构的边界（分层、依赖方向、状态存放位置）。

单纯的 bug 修复、参数调优、文案调整**不需要** ADR（写进
[`../../CHANGELOG.md`](../../CHANGELOG.md) 即可）。

## 模板

```markdown
# NNNN 标题

- 状态：提议 / 已接受 / 已废弃（被 NNNN 取代）
- 日期：YYYY-MM-DD
- 关联：相关代码路径 / issue / 审计条目

## 背景
（是什么问题逼着做决定；给出可核查的证据：文件:行、实测数字）

## 决策
（选了什么，边界在哪：支持什么、明确不支持什么）

## 备选方案
（各自代价；为什么没选）

## 后果
（正面/负面后果；什么情况下应该重新审视这条决策）
```
