# 网页端使用说明

网页端是同一套计算内核的交互界面：**简易模式**面向日常使用，**高级模式**暴露全部参数，
两者共用同一执行链路、同一份运行记录与产物。命令行入口见 `README.md` §3（`screen.py`）。

## 1. 启动

```bash
bash run_web.sh              # 默认 http://127.0.0.1:5000/
bash run_web.sh --port 8000  # 指定端口
```

- 简易模式：`http://127.0.0.1:<端口>/`
- 高级模式：`http://127.0.0.1:<端口>/advanced`（参数表单、运行记录、结果与报告目录）

首次使用前先装依赖：`pip install -r requirements.txt`（如需虚拟环境，`python3 -m venv .venv` 后
用 `.venv/bin/python`；`run_web.sh` 会自动优先使用 `.venv/bin/python`）。

## 2. 不配置大模型也能用

大模型**只用于把自然语言指令转成结构化任务与撰写结论文字**，不参与打分与排序。因此：

| 功能 | 是否需要大模型 |
| --- | --- |
| 表单参数发起筛选、查看运行记录与产物、下载 CSV/报告/位姿 | 不需要 |
| 自然语言对话（"帮我筛一下这个库"）、Agent 自动编排与结论撰写 | 需要 |

## 3. 配置大模型（可选）

复制模板并填入自己的密钥（`config/.env` 或工作目录 `.env`）：

```bash
cp .env.example .env
# 编辑 .env：LLM_BASE_URL / LLM_API_KEY / LLM_MODEL
```

`.env.example` 列出了全部可配置项（接口地址、密钥、模型名、超时等）。密钥只保存在本地，
不会写入运行记录与报告。

## 4. 主要接口（供复核与自动化调用）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/api/health` | 健康检查与环境自检 |
| `POST` | `/api/agent/stream` | 提交任务（SSE 流式返回进度、结果与产物链接） |
| `POST` | `/api/runs/{run_id}/...` | 运行控制（取消、断点续跑等） |
| `GET` | `/api/runs` `GET /api/runs/{run_id}` | 运行列表与详情（含产物、下载链接） |
| `GET` | `/api/settings` `POST /api/settings` | 读取/保存设置（引擎、参数默认值、界面偏好） |
| `POST` | `/api/uploads` | 上传受体结构或分子库 |

完整契约见仓库中的 `docs/api.md`；网页端与接口共用同一份运行记录，界面上的每次运行都能在
`var/runs/<run_id>/` 里找到对应的输入、参数、结果与日志（提交包内不含运行记录）。

## 5. 提交包中的网页端包含哪些内容

| 目录 | 内容 |
| --- | --- |
| `web/` | 前端静态资源（简易模式、高级模式、共享渲染与样式） |
| `config/` | 配置：Agent 提示词与工具绑定、设置默认值、内置受体注册表；`.env.example` 为密钥模板 |
| `assets/` | 内置资源：受体库、示例分子库、提示词模板；**不含**使用者上传数据（`assets/uploads`）、缓存与第三方工具二进制 |
| `run_web.sh` / `start.sh` | 网页端启动脚本（含环境自检的一键脚本） |
| `src/docking_agent/api/` | 服务与接口实现（与命令行入口共用计算内核） |

网页端的所有计算都落在 `src/docking_agent/core/`（对接、配体准备、口袋检测、质子化、排序），
与 `screen.py` 完全一致；因此网页端结果可以用命令行逐条复核。
